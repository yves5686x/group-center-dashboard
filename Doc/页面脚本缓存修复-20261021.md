# 页面脚本缓存修复（2026-10-21）

修复镜像：`ghcr.io/yves5686x/group-center-dashboard:1.8.16-rc.3`。后端继续使用 `ghcr.io/yves5686x/group-center:1.8.10-rc.4`。

## 故障与原因

飞牛 `172.22.22.1:8080` 从首页进入 GPU 看板时复现 `Cannot read properties of undefined (reading 'call')`，堆栈指向 `src/utils/machinePresentation.ts` 模块的加载。任务查询也依赖该模块。后端版本、机器列表和查询选项响应正常。

发布产物的 `umi.js`、`common-async.js`、各页面脚本和预加载脚本没有内容指纹，但 Nginx 对所有 JS/CSS 设置了缓存一年。升级后旧公共脚本和新页面模块混用，缺失新模块并触发全局错误。将同一份飞牛发布文件经新的缓存来源加载后，从首页进入 GPU 看板正常，确认了浏览器缓存造成的版本混用。

## 修复

- 开启构建内容指纹，入口、共享、异步页面和预加载脚本的 URL 随内容变化。
- 仅带指纹的资源使用长期缓存；无指纹资源使用 `no-store`，HTML 保持不缓存。
- 在布局的页面内容处隔离错误，切换路径重新创建错误边界；页面失败后菜单仍可用。
- 发布检查验证全部 JS/CSS 文件及 HTML 引用有指纹，并在真实容器中检查缓存头。

## 验证

- 前端类型检查、生产构建通过；静态资源缓存检查的 4 项测试通过。
- 保留旧版浏览器缓存后，在同一来源切换到修复版，任务查询成功打开。
- 使用飞牛真实只读接口，连续点击 GPU 看板、任务查询、统计信息均无脚本错误。
- 临时验证服务注入共享模块故障，页面显示局部错误提示；点击返回首页恢复正常。故障注入只作用于本机临时测试服务，没有修改飞牛服务或实际数据。

## 飞牛更新

在现有 Compose 中仅更新 web 的 image 为 `1.8.16-rc.3`，保留 backend、原项目名、数据库、端口和数据卷，然后拉取并重建 web：

```bash
docker compose pull web
docker compose up -d --no-deps web
```

如使用自定义文件名，为命令添加 `-f 实际文件名`。浏览器刷新后应加载带指纹的脚本；已处于错误页的旧标签页可先强制刷新（Windows/Linux Ctrl+Shift+R，macOS Command+Shift+R）。升级不需要修改数据库或清空浏览器站点数据。

升级前暂时恢复：直接在飞牛页面强制刷新，让同版本脚本重新加载。无需降级后端，也无需改动 Agent。
