# 深浅主题配色排查与修复

## 范围与状态

本次扫描整个 `src` 的颜色、透明度、标签和图表配置；检查首页、GPU 看板、硬盘看板、任务查询、统计信息（五个分页）、高级管理、反馈报告及 GPU 筛选区域。重点处理自定义颜色和小字可读性。

本次改动纳入前端 `1.8.16-rc.6`。预览使用模拟数据，发布不自动更新飞牛或生产服务器，未修改生产数据库和 Agent。

## 发现与处理

| 位置 | 原因 | 修复 |
| --- | --- | --- |
| 多卡 1/2、2/2 标签 | 以背景的反色作为文字色，不能保证明暗区别 | 保留同任务同色，改成淡底、清晰文字和有色边框；去掉文字链接样式 |
| 用户、项目排名标签 | 浅蓝、浅绿底配白字 | 使用同一套标签配色计算 |
| 状态与告警标签 | 预设蓝色、处理状态、黄色等小字在部分主题下不够清晰 | 公共 ReadableTag 按实际底色调整文字，保留状态含义和背景 |
| 首页监控、统计说明、刷新时间、筛选说明 | 固定 #666、#999，或过淡的辅助文字 | 跟随主题使用清晰的次要文字色 |
| 成功、告警、错误数值 | 直接把强调色用于小字 | 按卡片或浮层背景调整明暗 |
| 筛选按钮、常用入口图标与文字 | 固定蓝色渐变、白字或旧版暗色变量 | 使用主题淡底和经过对比度计算的强调文字色 |
| GPU、用户、项目、时间趋势图 | 图表主题默认又给标签叠加透明度；部分文字固定黑色 | 公共图表主题统一文字色和不透明度 |
| GPU 右键菜单 | 用一个固定背景色猜测当前主题 | 读取实际深浅主题状态 |
| GPU 显存、核心进度条 | 低占用时显存蓝色、核心绿色，规则不统一 | 两项共用数值分档：低于 40% 绿色，40%–79% 黄色，80%–100% 红色。红色表示占用或负载高 |

禁用状态、动画透明度和装饰色保留各自用途；本次没有把每个装饰色都改成正文色。

## GPU 柱状图

“GPU型号在各服务器的任务数对比”每根柱下方固定显示服务器名和 GPU 型号，柱顶固定显示任务数，包括 0 个。同一服务器同一型号仍先汇总任务数。改用当前图表库支持的分类、配色和坐标轴配置，避免同型号跨服务器重叠。

名称不再截断，关闭自动隐藏和旋转。按名称长度预留每根柱的宽度；窄屏或服务器较多时，图表区域可单独横向滚动。390 像素设备宽度下检查：页面自身无横向溢出，图表内容宽 512 像素、可视区宽 325 像素。

## 核对结果

- 原多卡 32 种配色中，11 种文字对比度低于本项目采用的 4.5 目标，最差约 1.06。
- 新标签在两种主题下检查全部内置色阶及原排名颜色：文字对比度至少 4.5，彩色边框与底色至少 3。
- 实际页面读取标签的文字与背景色，核对首页、GPU 任务、硬盘告警、排名及查询结果；主题切换动画结束后检查。
- GPU 实际页面读取 26 条进度条的颜色，在两种主题下均为 3 档，同一档位的显存和核心使用完全相同的颜色。
- 类型检查、全项目样式检查、生产构建通过；7 项配色测试、4 项静态缓存测试通过，26 个带版本指纹的 JS/CSS 资源通过检查。
- Docker 构建流程已加入配色测试；本机未运行 Docker 构建；发布流程会在 GitHub Actions 中构建并验证实际 Nginx 容器。

这里的数值用于验证本次修复，不代表完整的无障碍认证，也不代表所有浏览器、所有业务数据组合均已穷尽。

## 2026-10-22 调整

红绿灯统一为绿色 `#22c55e`、黄色 `#f2c037`、红色 `#ef4444`，集中维护于 `src/utils/StatusColors.ts`。显卡显存、核心、硬盘及系统内存用量共用分档：低于 40% 绿色，40%–79% 黄色，80% 及以上红色。

首页 Ping、Agent 和代理在线均使用绿色，离线或检查失败使用红色；注意和告警使用黄色。修正 Agent 在线原先为蓝色、离线为橙色，以及代理 100% 可用率固定显示黄色的问题。首页状态图标、卡片侧边标记、代理成功率进度条、任务及硬盘告警标签共用这组颜色。成功率和可用率越高越好，保持与用量相反的分档方向。

进度条和状态图标直接使用色板；标签采用同色系淡底与清晰正文，语义数字按背景微调文字明暗。信息提示、图表系列及多卡任务分组色仍保留各自含义。

本次新增配色核对：深浅主题下共读取 54 个标签、92 条用量进度条，验证标签文字可读、首页在线图标与低占用绿色一致，以及 GPU 和硬盘的三档色值完全相同。首页可用率同时兼容数字与百分比字符串。
