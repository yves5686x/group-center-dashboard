# GPU 卡时统计：本地预览

运行 `npm run preview:server`，访问 `http://127.0.0.1:18771/statistics`，页面顶部可切换“任务统计”和“GPU 卡时统计”。`/statistics?preview=gpu-hours` 可直接打开卡时视图。

该命令需要已有的 `server.329509.xyz:233` SSH 登录权限。它启动本机 SSH 转发（18881）、只读接口代理（18882）和前端（18771）；所有监听均绑定 127.0.0.1。退出时清理自己启动的子进程，不替换远程文件或容器。

切换入口同时用于开发和正式环境。`/statistics` 默认显示原任务统计：GPU 使用统计、用户统计、项目统计、时间趋势、活动时间分布均保留。切换视图时保留各自的筛选与栏目状态。生产环境默认打开任务统计，可切换 GPU 卡时统计（`/statistics?mode=gpu-hours`）。

已在浏览器确认：原活动时间分布可正常打开；切换到卡时统计再返回，仍保留活动时间分布的选中状态；原 GPU 使用统计也可正常返回。切换入口、TypeScript、样式和生产构建均已验证。

## 数据与计算边界

真实数据模式关闭所有 Umi mock。原任务统计直接读取 server 现有统计接口；卡时版通过现有任务查询接口完整读取所选区间的结束记录，并补充七台 GPU 主机的当前快照。历史分页使用 ID 游标，加载失败时不展示不完整总计，也不会回退到示例数据。

只读代理只允许 GET、HEAD，以及 `/web/open/gpu-tasks/query` 的查询 POST；清缓存、修改订阅、设置修改和删除等请求均被拦截。卡时加载器还校验代理来源标记，防止开发 mock 被误当成真实数据。

正式页面只读取真实数据，不提供示例回退。固定日期的样例已移至 `scripts/fixtures`，只用于计算测试。生产环境通过同源 nginx 读取接口，不依赖 SSH、本地代理或预览来源标记。

真实 Agent 的多卡 rank 使用不同任务 ID，不能直接将其当作独立任务。卡时计算使用逐卡起止记录，不从原统计接口的 totalRuntime 或 worldSize 推断占用。

1. 按服务器 + GPU 标识合并重叠区间，计算物理 GPU 卡时。
2. 按服务器、用户、项目、主进程和启动批次合并 DDP rank；普通任务按 PID 和开始时间分组。PID 重用不会合并不同启动批次。缺少主进程的多卡记录保守分开并标为估算。
3. 按统计窗口裁切；运行中任务仅计算到最后可靠采集时间。
4. 用户、项目分别计算占用卡时。多人共享一张卡时，用户占用时间可重叠，不要求用户合计等于物理总卡时。
5. 按上海自然日拆分趋势。首尾日期可能仅覆盖部分时段；跨天任务会计入多个日期的当日任务数。
6. 当前快照无法证明同一张卡自任务启动以来持续使用，运行中任务的回溯占用明确标为估算。多卡记录不完整时只计观测到的卡，不按 worldSize 补齐；缺少结束记录且已不在快照中的任务不虚构时长。

2026-10-23 实际接入核对：周数据一次读取 668 条结束记录、13 条运行中记录；约 2,483.0 卡时，581 个逻辑任务、16 位用户、七台服务器。数值随刷新和滚动时间窗口变化。逐服务器与逐日卡时相加均与物理总卡时一致；该次无分组信息缺失、无多卡记录缺卡、无实时快照失败。

原版任务统计按后端原有口径及缓存展示；卡时版包含可读到的运行中任务，且按物理 GPU 去重，因此两套统计的任务数或时长不必完全一致。本次前端版本为 `1.8.16-rc.8`，后端继续使用 `1.8.10-rc.4`。发布与 server 部署结果见同目录发布记录。
